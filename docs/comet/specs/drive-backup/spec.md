# Drive 备份与授权（drive-backup）

## 目标行为

### Google 授权（refresh token 持久化）

- 首次连接 Google Drive 时走 OAuth 授权，请求参数包含 `access_type=offline` 与 `prompt=consent`，授权后获得 refresh token
- refresh token 与用户隔离存储（沿用 `buildUserStorageKey` 体系）
- 已持有 refresh token 的用户再次打开应用时，自动用 refresh token 静默换取 access token，不弹出授权页；仅在 token 失效或被撤销时才提示重新授权
- access token 过期时自动刷新，用户无感

### 自动备份

- 记录数据（健康记录、指标分类、变更日志）发生任何变更（增、删、改、Excel 导入、报告导入）后，防抖触发静默上传 Google Drive
- 默认开启；设置中提供开关（沿用/扩展现有"导入后自动上传"开关），关闭后回退手动上传
- 上传成功/失败在 UI 有轻量状态提示（不阻断操作）；失败不重试阻塞用户，下次变更再次尝试

### 拉取保护

- 从云端拉取前对比云端备份与本地数据的更新时间
- 云端更新时弹窗提示并显示两侧时间，由用户确认后才覆盖本地；本地更新或相同时按现有逻辑处理
- 不做自动合并

### 附件同步

- 附件（报告照片/PDF）上传至 Google Drive 作为持久层；本地保留缓存用于离线查看与预览
- 附件总量不再受 localStorage 20MB 限制；单文件上限维持 10MB 起步（可配置常量）
- 从云端备份恢复后，附件完整可用（含预览）
- 附件上传失败时记录状态并允许重试，不阻塞记录本身的上传

## 约束

- 健康数据与附件绝不写入任何数据库
- 凭据不进代码仓库；API 凭据仅在用户浏览器本地
- 用户可见文案全部中文
